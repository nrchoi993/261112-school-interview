질문 은행

특성화고 면접에서 자주 나오는 유형(빈출)과 계열별 예상 질문이에요. 질문마다 면접관이 무엇을 보는지 함께 적어 두었어요.

서울 특성화고 67개교 찾기

서울시교육청 2027학년도 특성화고 입학전형 요강을 바탕으로 학교별 모집 학과·정원, 특별전형, 면접 배점을 정리했어요. 학과 이름을 누르면 그 학교·학과로 바로 설정되고, 계열은 학과에 맞춰 자동으로 분류돼요.

모집 정원과 전형 방법은 요강 발표(2026.8.) 뒤 바뀔 수 있어요. 원서 접수 전에 학교 홈페이지 공지를 꼭 확인하세요.

계열별로 배우는 것

계열마다 배우는 내용, 자격증, 진로예요. 지원동기·학업계획 답변의 재료로 쓰세요.

2027학년도 서울 특성화고 전형 일정

서울 특성화고 67개교가 같은 일정으로 신입생을 모집해요. 면접은 특별전형에서 학교별로 진행돼요.

    요강으로 본 미래인재 특별전형

    67개교 요강을 비교해 보면 미래인재 특별전형은 대부분 100점 만점에 이렇게 평가해요.

    심층면접 60점 안팎

    대부분 면접(일부 학과는 실기 포함)에 60점을 주고, 70점까지 주는 학교도 있어요. 당락을 가르는 가장 큰 요소예요.

    출결 20~30점

    중학교 3년 출결을 봐요. 61개교가 미인정 지각·조퇴·결과 3회를 미인정 결석 1일로 계산해요.

    봉사 10~20점

    67개교 모두 봉사 시간과 관계없이 만점을 줘요.

    면접은 보통 1지망 학과로

    55개교가 여러 학과를 지망해도 1지망 학과 면접 점수를 그대로 써요. 66개교는 면접에 빠지면 불합격이에요.

    성적보다 태도와 의지

    특별전형 생활기록부는 수상 경력과 교과 성적을 빼고 내요. 반면 일반전형은 67개교 모두 면접 없이 내신 순으로 뽑아요.

    가산점 확인하기

    22개교가 입학설명회·진로캠프·전공체험 참여나 수상 등에 가산점을 줘요. 학교·학과 정보 탭에서 학교별로 확인하세요.

    면접 당일 체크리스트

    답변 내용만큼 태도와 말하는 방식도 평가돼요.

    결론부터 말하기

    첫 문장에 답을 말하고, 이어서 이유와 경험을 붙이세요. 면접관이 내 답을 놓치지 않아요.

    1분 안팎으로 답하기

    한 답변은 말하기 기준 1분, 글자로는 250~350자 정도가 적당해요.

    경험 하나를 구체적으로

    "열심히 했다"보다 "2학년 때 6개월 동안 매주 코딩 동아리에서…"처럼 언제·무엇을·어떻게를 넣으세요.

    학교 요강의 금지 사항 확인

    학교에 따라 이름·출신 중학교·부모님 직업 언급을 금지해요. 요강의 면접 유의사항을 꼭 읽으세요.

    단정한 복장과 바른 자세

    교복이나 단정한 옷, 바른 자세, 또렷한 목소리면 충분해요. 인사로 시작하고 인사로 끝내세요.

    모르는 질문엔 솔직하게

    "잘 모르지만, 제 생각에는…"처럼 솔직하게 시작한 뒤 아는 만큼 차분히 말하세요.

    교사 모드

    학생 대시보드, API 상태 표시와 이 탭은 교사 모드에서만 보여요. AI 오류도 학생에게는 간단한 안내로만 보여요.

    교사 비밀번호 바꾸기

    교사 비밀번호

    비밀번호는 서버 저장소에 솔트+해시로 저장돼서 어느 컴퓨터에서나 같아요. 처음 비밀번호는 Vercel 환경 변수 TEACHER_PASSWORD(없으면 00000000)이고, 기본 비밀번호로 들어오면 새 비밀번호를 정해야 대시보드를 볼 수 있어요. 비밀번호를 잊었다면 Upstash 콘솔에서 iv:cfg:teacher 키를 지우면 처음 비밀번호로 돌아가요.

    OpenAI Responses API 실습

    브라우저가 이 사이트의 서버 함수(POST /api/ai)에 요청하면, 서버가 키를 붙여 OpenAI Responses API(POST /v1/responses)를 호출해요. 마지막 요청과 응답 원문을 보면서 구조를 익혀 보세요. 키가 없으면 규칙 기반 평가로 동작해요.

    짧은 요청을 실제로 보내 봐요. 성공해야 상태가 ‘요청 성공’으로 바뀌어요.
    보안 안내

    API 키는 Vercel 환경 변수 OPENAI_API_KEY에만 있고 브라우저 코드에는 들어가지 않아요. 서버 함수는 로그인한 학생·교사의 요청만 받고, 한 사람당 1시간 요청 수를 제한해요. 그래도 OpenAI 대시보드의 사용 한도(Limits)는 낮게 설정해 두세요. VITE_로 시작하는 환경 변수에 키를 넣으면 브라우저 코드에 들어가니 쓰지 마세요.

    요청·응답 구조 읽는 법
    
        
      
          
    • model: 사용할 모델 이름이에요. 서버 환경 변수 OPENAI_MODEL(기본 gpt-6.1-terra)을 써요. 브라우저가 모델을 바꿀 수 없게 서버가 정해요.
      • 
          
    • instructions: 모델에게 주는 역할·규칙(개발자 메시지)이에요. 요청마다 새로 보내야 해요.
      • 
          
    • input: 대화 기록이에요. {"role":"user"|"assistant","content":"…"} 메시지를 차례로 담아 보내서 이어지는 질문에도 맥락을 기억하게 해요(최근 30개).
      • 
          
    • text.format: 답변 평가는 json_schema 형식(구조화 출력)으로 받아 평가표를 그려요.
      • 
          
    • store: false: OpenAI에 응답을 저장하지 않아요. reasoning.effort: "low"로 추론을 짧게 해 응답 속도를 높여요.
      • 
          
    • 응답의 output 배열에는 추론(reasoning) 항목이 먼저 올 수 있어요. type: "message" 항목의 content 중 type: "output_text"인 text를 모아야 해요.
      • 
          
    • status가 incomplete면 답이 잘린 것이고, usage에서 입력·출력 토큰 수를 확인할 수 있어요.
